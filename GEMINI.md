## Core Development Guidelines
1. **Architecture:** MVVM with Unidirectional Data Flow (UDF). Composable -> ViewModel -> Repository -> Room / Retrofit GitHub API.
2. **State Management:** Expose immutable `StateFlow<UiState>` from ViewModels; collect with `collectAsStateWithLifecycle()` in Composables.
3. **Testing & CI Parity:** Never break unit test suite or CI builds. Prior to pushing or opening a PR, run unit tests locally (`.\gradlew.bat testDebugUnitTest --no-daemon`).
4. **Environment Isolation:** Never commit machine-specific paths into repository files. Secrets belong in `.env` (ignored by git).
5. **GitHub Authentication:** Always execute `C:\Users\rogal\workspaces\Set-GhToken-Antares.ps1` (or load `$Env:GH_TOKEN` from it) prior to executing Git push / GitHub CLI (`gh`) operations for `AntaresAndBharani`.
6. **CI/CD Lifecycle & Definition of Done:**
   - **Release Workflow:** The repository contains [`release.yml`](.github/workflows/release.yml), triggered manually via `workflow_dispatch` to build release APKs and publish GitHub Releases.
   - **Agent Completion Gate:** Development is complete when local tests pass, code compiles cleanly, changes are committed with clear messages, and PR is verified.

## Agentic SDLC Pipeline
The project implements the **Graph Engineering Autonomous SDLC Pipeline** via the Local CLI Pipeline executor (Windows Task Scheduler driving `claude.exe` and `agy.exe`):

- **As PO, draft a User Story** using the `user-story.yml` issue template.
  When ready, label it `status:ready-for-architect` to hand off.
- **Label Taxonomy & Lifecycle:**
  - `status:definition` — Still drafting by PO.
  - `status:ready-for-architect` — PO says go; triggers Architect (`GDD-Architect` / `claude-sonnet-5`).
  - `status:needs-po-input` — Architect escalated a conflict/business call; PO answers, then relabels `status:ready-for-architect`.
  - `status:review` — Architect created/updated this story's subtask batch; handed off to Three Amigos.
  - `status:needs-revision` / `status:needs-clarification` — Three Amigos bounced it back to Architect.
  - `status:awaiting-approval` — Subtask cleared for pickup by Three Amigos.
  - `status:ready` — Story cleared by Three Amigos; triggers Dev & Test.
  - `status:in-progress` — Subtask currently being implemented by Dev & Test (`GDD-ThreeAmigosDevTest` / `agy.exe`).
  - `status:done` — Set automatically once every subtask under a story is closed.
  - `review:approved` — PR Review (`GDD-PRReview` / `claude.exe`) approved PR; triggers merge.
  - `review:changes-requested` — PR Review requested changes; triggers Dev & Test fix-up pass.
  - `tech-debt` / `enhancement` — Non-blocking follow-ups filed by PR Review; periodically triaged by Backlog Triage (`GDD-BacklogTriage`).
  - `origin:backlog-triage` — Set on stories generated by Backlog Triage to use cost-optimized Sonnet model.
